# Задание стажировки №2: зум в стиле Camtasia

## Что нужно было сделать

Во время записи видео можно «увеличить» картинку вокруг курсора (как в Camtasia): плавно приблизить,
подержать, плавно вернуть. Записать это прямо в видео Playwright не умеет, поэтому делается в два шага:

1. **При записи** (`qscript.py`) программа запоминает *моменты*: «в 3.0 с приблизить вокруг точки (640, 360),
   в 8.0 с вернуть». Это либо клавиша **F5** (оператор жмёт руками), либо вызов `window.__zoomAt(x, y)` из сценария.
   События сохраняются в файл рядом с видео: `<видео>.zoom.json`.
2. **После записи** (`apply_zoom.py`, ffmpeg) видео перерисовывается: плавный наезд → удержание → плавный отъезд.
   Этот шаг работает **внутри Docker**: отдельный контейнер `worker` берёт загруженные видео из PostgreSQL,
   обрабатывает и записывает ссылку на готовое видео обратно в базу.

## Что в папке `internship2`

| Файл | Для чего |
|------|----------|
| `qscript.py` | сценарий записи + F5 + `window.__zoomAt` + цветное кольцо + запись `.zoom.json` |
| `apply_zoom.py` | обработка видео через ffmpeg (`--dry-run`, `--ffmpeg`) |
| `capture_video.py`, `video_client.py` | рекордер: теперь загружает и sidecar, ждёт обработанное видео и показывает его |
| `web_service.py`, `db.py` | сервис (Flask + PostgreSQL): приём sidecar, `/jobs/...`, новые столбцы в таблице |
| `worker.py` | фоновая обработка: берёт `pending`-видео, запускает `apply_zoom`, пишет результат в БД |
| `Dockerfile`, `docker-compose.yml` | образ с ffmpeg; сервисы `web`, `worker`, `db` |
| `tests/`, `pytest.ini` | тесты pytest |
| `README.md`, `requirements*.txt`, `.github/workflows/tests.yml` | документация, зависимости, CI |

## Что нужно установить

Ничего нового: Docker Desktop у вас уже стоит. ffmpeg на Windows **ставить не нужно**, он находится внутри контейнеров.
(Нужен только если захотите запускать `apply_zoom.py` прямо на Windows, тогда укажите путь опцией `--ffmpeg`.)

## Как сделать

1. **Распакуйте** архив в `C:\Users\Ann\Downloads\тестовое\стажировка\internship2`.
2. **Остановите прошлый стек** (он занимает порт 8000):
   ```
   cd C:\Users\Ann\Downloads\тестовое\стажировка\internship1
   docker compose down
   ```
3. **Запустите новый стек** (первая сборка дольше обычной: ставится ffmpeg):
   ```
   cd C:\Users\Ann\Downloads\тестовое\стажировка\internship2
   docker compose up -d --build
   docker compose ps
   ```
   Должны работать три контейнера: `db`, `web` (healthy), `worker`. Проверка ffmpeg внутри:
   ```
   docker compose exec worker ffmpeg -version
   ```
4. **Запустите рекордер** (в той же папке `internship2`, там лежит `input.csv`):
   ```
   python -m pip install -r requirements-recorder.txt
   python capture_video.py --server http://127.0.0.1:8000 --view-seconds 10
   ```
   В консоли: `zoom events: 4 -> ...zoom.json`, `uploaded: ...`, `waiting for the zoom step on the server ...`,
   `zoomed: http://127.0.0.1:8000/media/....zoomed.webm`. Потом в Chromium откроется **уже увеличенное** видео.
5. **Проверьте F5 вручную**: запустите `python capture_video.py --no-zoom` и пока идёт запись, нажимайте F5 в окне
   браузера: первое нажатие = приближение в точке курсора (зелёное кольцо), второе = отъезд (красное кольцо).
6. **Проверьте обработку отдельно** (без Docker хватит `--dry-run`, он ffmpeg не требует):
   ```
   python apply_zoom.py --video "video\Acme GmbH.webm" --dry-run
   ```
   Реальную обработку можно сделать внутри контейнера:
   ```
   docker compose exec worker python3 /app/apply_zoom.py --video /app/uploads/Acme_GmbH.webm
   ```
7. **Запустите тесты**:
   ```
   python -m pip install -r requirements-dev.txt
   python -m pytest -v
   ```
8. **Посмотрите результат в базе**:
   ```
   docker compose exec db psql -U video_user -d videos -c "select id, company_name, process_status, processed_video_url from videos"
   ```

## Что должно получиться

- `video\<Компания>.webm` и рядом `<Компания>.zoom.json` (файл есть только если были события).
- В видео: зелёное кольцо при приближении, красное при отъезде; на готовом видео плавный зум вокруг точки курсора,
  без дёрганья, с возвратом к обычному масштабу; несколько зумов в одном видео; если зум не закрыт, он держится до конца.
- В PostgreSQL у видео `process_status = done` и заполнен `processed_video_url`.
- `python -m pytest`: все юнит-тесты проходят. На Windows без ffmpeg тесты с реальным ffmpeg будут пропущены (`skipped`),
  тесты стека проходят при запущенных контейнерах.

## Важно знать

- **Маленькая магента-точка 8×8 px** в левом верхнем углу на 0.3 с появляется при *первом* зум-событии. Это калибровка:
  видео в Playwright стартует позже, чем идут часы событий, причём на разное время (у меня 0.4-0.9 с). `apply_zoom.py` находит эту точку
  в видео и сдвигает события; ошибка после этого не больше одного кадра (в 6 запусках до 0.023 с против ~0.53 с без калибровки).
  Без зум-событий точки нет.
- Кольцо-индикатор тоже попадает в видео (так требует задание).
- F5 работает, когда окно браузера в фокусе; страница при этом не перезагружается.
