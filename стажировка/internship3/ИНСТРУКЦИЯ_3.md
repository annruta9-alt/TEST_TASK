# Задание стажировки №3: импорт компаний и Impressum через DeepSeek

## Что нужно было сделать

1. В веб-сервис (Docker из задания 1) добавить **список компаний**: страница с формой загрузки CSV, запись в PostgreSQL,
   чтение сохранённых данных через веб-сервис.
2. Написать отдельную программу `enrich_companies.py`. Она берёт компании из PostgreSQL, открывает сайт (колонка `Web`),
   находит страницу **Impressum / Imprint**, отправляет её текст в **DeepSeek** и получает структурированный JSON
   (название, адрес, Handelsregister, USt-IdNr., телефон, e-mail, ответственное лицо). Результат пишется обратно в базу
   вместе со **статусом** (0 OK, 1 нет ссылки, 2 ничего не распознано, 3 адрес неполный, 4 ошибка, 5 нет сайта).
3. Главная инженерная часть: **экономия токенов**. Страница Impressum «раздута» меню, cookie-баннерами и футером, поэтому в
   DeepSeek уходит только юридический блок: обрезается голова (до заголовка «Impressum / Angaben gemäß § 5…») и хвост
   (через 400 символов после последнего телефона, e-mail, USt-IdNr., HRB или «Geschäftsführer»).

## Важно про ключ DeepSeek

Ключ нельзя хранить в коде и в git. Он лежит **только в файле `.env`** на вашем компьютере (этот файл исключён из git и из образа Docker).
В файлах проекта ключа нет, я это проверил. Ключ был отправлен в чат, поэтому не пересылайте его дальше, не коммитьте
`.env` и по возможности замените ключ после сдачи задания.

## Как запустить, по шагам (PowerShell)

1. **Распакуйте** архив в `C:\Users\Ann\Downloads\тестовое\стажировка\internship3`.
2. **Остановите прошлый стек** (он занимает порт 8000):
   ```
   cd C:\Users\Ann\Downloads\тестовое\стажировка\internship2
   docker compose down
   ```
3. **Создайте `.env` с ключом:**
   ```
   cd C:\Users\Ann\Downloads\тестовое\стажировка\internship3
   copy .env.example .env
   notepad .env
   ```
   В строке `DEEPSEEK_API_KEY=` вставьте ключ сразу после знака равенства (без пробелов и кавычек), сохраните файл.
4. **Запустите стек:**
   ```
   docker compose up -d --build
   docker compose ps
   ```
   `web` и `db` должны быть `healthy`. Проверка: http://localhost:8000/health показывает `{"status":"ok"}`.
5. **Загрузите CSV через браузер:** откройте http://localhost:8000/upload_companies, выберите `companies.csv`, нажмите Upload.
   Ответ: `{"imported": 2, "updated": 0, "skipped": 0, "total_rows": 2}`. Загрузка того же файла ещё раз даст `"updated": 2` и без дублей.
6. **Посмотрите данные:** http://localhost:8000/companies (все) и, например, `http://localhost:8000/companies/nutrimmun%20GmbH`. У новых компаний `status` пустой (`PENDING`).
7. **Сухой прогон без трат токенов** (покажет, как оптимизация режет текст):
   ```
   docker compose run --rm enrich --dry-run
   ```
   В выводе будут строки вида `text 14230 -> 612 chars (~3557 -> ~153 tokens, -96%)`. Если для сайта пишет `no Impressum/Imprint link`, статус будет 1.
8. **Реальный запуск, сначала одна компания:**
   ```
   docker compose run --rm enrich --limit 1
   docker compose run --rm enrich
   ```
   Один запрос к DeepSeek на компанию (при пустом ответе или временной ошибке до трёх попыток).
9. **Проверьте результат:** http://localhost:8000/companies. В каждой компании заполнены `impressum_url`, `legal_name`, `postal_address`,
   `handelsregister`, `vat_number`, `phone`, `email`, `responsible_person`, `raw_json` и `status` (0 или 3 для успеха).
   Повторная загрузка CSV не стирает эти данные.

Полезно знать: повторный запуск `enrich` берёт только компании со статусом не 0; `--company "nutrimmun GmbH"` принудительно обрабатывает одну;
`--status 4` повторяет только ошибки.

## Что должно получиться

- Форма загрузки работает, `/companies` и `/companies/<имя>` отдают данные, повторный импорт идемпотентен и не затирает результаты.
- Для каждой компании в логе видно «до → после» в символах и токенах.
- Статусы: 0 если найдены поля и адрес полный (индекс, город, улица, номер дома); 3 если адрес неполный; 2 если ничего не распознано; 1 если нет ссылки; 4 при сбоях сети/HTTP/DeepSeek (пакет не останавливается); 5 если `web` пустой.
- Если сайт блокирует автоматические запросы (ответ 403), статус будет 4: это норма, не ошибка проекта.
